# LibreSpydus desktop — build contract (GPUI + gpui-kit)

A desktop LibreSpydus in Rust, on **GPUI** (Zed's UI framework) with longbridge's **gpui-kit**
components. The app calls the shared core `core/` (crate `librespydus-core`) **directly as a Rust
crate**, without UniFFI. It does what the phone apps do, with the same copy and design tokens,
laid out for a window. This file is the contract every desktop worker reads first.

The gpui-kit API notes are in `docs/gpui-kit-notes.md`; read the crate sources rather than guess.
It builds on `docs/native-apps.md`, which stays authoritative for behaviour: the core API (§4),
the app architecture (§5), the screens (§6), the design and copy rules (§7). Where this file says
"as §x", do what native-apps.md §x says, with the desktop changes listed here. Read native-apps.md
§2, §4, §5 and §6 before you start.

| | Desktop |
|---|---|
| Display name | LibreSpydus |
| App id | `com.librespydus.desktop` |
| Platforms | macOS 13+ first (built and checked on this Mac). The code stays cross-platform: AppKit-only code lives in `src/platform/`, secrets go through the `keyring` crate. Windows and Linux builds come later. |
| UI | `gpui-kit = "=0.7.3"` (pins `gpui-pre =0.3.9`); `use gpui_kit::*` re-exports GPUI |
| Core | `librespydus-core = { path = "../core" }`, called directly; one tokio runtime (§5.1) |
| Secure store | OS keychain through `keyring` (macOS Keychain); memory in demo mode or with `--data-dir` |
| Package | `desktop/`: a standalone Cargo package `librespydus-desktop` (edition 2024, binary `librespydus`) with its own committed `Cargo.lock`. It is not a workspace with `core/`. |

## 1. Workflow (Orca supervised DAG, per-worker git worktrees)

- The integration branch is **`desktop`**. Each worker runs in its own Orca worktree branched from
  it, commits **only on its worktree branch**, and stops. The coordinator merges.
- **Workers run on the Orca SSH host `mini-knit`**, a Mac mini with these tools:
  - macOS 27, arm64, rustc 1.97.1;
  - **Command Line Tools only, no Xcode**, which is enough for GPUI;
  - **Python 3.9**: keep `design/scripts/*.py` 3.9-compatible, with no `match` statements and no
    `X | Y` outside annotations under `from __future__ import annotations`.
  - The coordinator works in the laptop checkout and fetches workers' branches from mini-knit.
- Workers never push, merge, rebase other branches or switch branches. They never touch the main
  checkout on mini-knit, `/Users/user/Project/personal/spydus_clone` (read-only for workers).
- Commit only files you own (§3). List any small fix outside them in your report.

| Wave | Tasks (parallel within a wave) |
|---|---|
| 1 | **D1** pipeline + shell + design system + app core + copy tooling |
| 2 | **D2** onboarding & account (library picker, sign in, Profile, My card) · **D3** Home + Search (+ Featured collections) · **D4** Book detail (+ Reserve, held status, renew, My Picks bookmark) · **D5** Your Books + My Picks |
| 3 (later, needs the user's OK) | the "confirm you're human" check (a `wry` helper process), desktop notifications (§5.8), Touch ID sign-back-in (§5.14), a packaged `.app`, Windows and Linux |

## 2. Safety rules (non-negotiable, every task)

native-apps.md §2 applies in full: **demo mode only** for anything account-related, **public GETs
only**, no sign-in with real credentials, no POST to a library, never touch a WAF check, never read
`.private/`. In addition:

1. Always run the app with **`--data-dir <dir>`**, a directory under
   `/tmp/librespydus-evidence/<task>/`. With `--data-dir`, every file goes there and secrets
   stay in memory. A worker never writes to the user's real app data or keychain.
2. Use **`--demo`** for every signed-in screen. Without `--demo`, stay signed out (public pages only).
3. Never stage `ios/LibreSpydus.xcodeproj/project.pbxproj` or `ios/Config/LibreSpydus-Info.plist`:
   they hold the user's uncommitted edits in the main checkout.
4. Launch the app only to take evidence, with `--evidence` (no activation or focus, fixed size and
   position) and `--screenshot`, so it quits by itself (`desktop/scripts/screenshot.sh`).

## 4. Core API

As native-apps.md §4, but in Rust: `librespydus_core::{SpydusClient, list_libraries, user_agent,
app::*, barcode::card_barcode, types::*, SpydusError}`. `SpydusClient::new(origin) -> Arc<Self>`.
Its methods take `&self`; most are `async fn`, and the saved-page reads and `origin()` are
synchronous. The free helpers (`is_digital_format`, `availability_summary`, `parse_due_date`,
`home_genres`, `home_shelves`, `account_holding`, `patron_item_record_url`, `patron_item_key`,
`encode_account_snapshot`, `decode_account_snapshot`, …) are plain functions in
`librespydus_core::app`. Never call `SpydusClient` from a screen: go through `LibraryBackend`
(§5.2).

## 5. App architecture (mirrors native-apps.md §5)

### 5.1 Runtime bridge (`src/runtime.rs`)
- The core needs tokio: reqwest and `spawn_blocking` panic outside a runtime, and GPUI's executor
  isn't tokio. One global multi-threaded runtime: `runtime::handle()`.
- `runtime::spawn_core(fut) -> impl Future<Output = T>`: spawn a `Send + 'static` future on the
  runtime and await its `JoinHandle` from any executor. A screen awaits that inside
  `cx.spawn(async move |this, cx| …)` and applies the result with `this.update(cx, …)`.
- `img(url)` loads nothing until the app has an HTTP client. `runtime::HttpClient` implements
  gpui's `http_client::HttpClient` with reqwest on the same runtime, sends the core's
  `user_agent()`, and is installed with `Application::with_http_client`.

### 5.2 `LibraryBackend` (`src/backend/`)
A trait mirroring iOS `ios/LibreSpydus/Core/LibraryBackend.swift` method for method, Rust-named.
Async methods return `BoxFuture<'static, Result<T, SpydusError>>`, so screens hold
`Arc<dyn LibraryBackend>`. `origin()`, `is_demo()`, `set_verification_cookie()` and the saved-page
reads are synchronous.
- **`CoreBackend`** wraps one `Arc<SpydusClient>`, runs every call through `runtime::spawn_core`,
  sets `set_saved_pages_dir`, and logs `⏱ app <call>: <ms> total` in debug builds.
- **`DemoBackend`** ports `ios/LibreSpydus/Core/DemoBackend.swift` (§5.4): public reads go to a
  real `CoreBackend`, apart from the offline demo catalogue. Account data comes from the iOS demo
  fixtures, included at build time with
  `include_str!("../../../ios/LibreSpydus/Resources/DemoData/demo-*.json")` so there's one copy.
  The rules are the same: `demo`/`demo` signs in, mutations wait 600 ms, renew waits 2 s and adds
  21 days except IRN `18000002`, and `--demo-refresh-fails` makes refreshes fail.
- **`FakeBackend`** (test-only, as iOS `TestSupport.swift`) gives canned answers and records calls.

### 5.3 `AppState` (`src/state/`)
A GPUI entity, reachable with `AppState::global(cx) -> Entity<AppState>`. It ports
`ios/LibreSpydus/Core/AppModel.swift`, minus the alerts and Face ID parts. D1 provides at least:
- **Library:** `library()`, `library_name()`, `backend()`, `select_library(info, cx)`, `is_demo()`.
- **Session:** `is_signed_in()`, `session()`, `account_name()`,
  `sign_in(username, password, cx) -> Task<Result<(), UserFacingError>>`, `sign_out(cx)`.
- **Errors:** `report(&SpydusError, cx) -> UserFacingError`. As native-apps.md §5.2, with one
  desktop difference: `HumanVerificationRequired` gives the same "library unavailable" error as
  iOS's `verificationUnavailable`, because v1 has no web view. `NotLoggedIn` clears the session and
  asks for sign-in.
- **Account (§5.2a):** `account() -> &AccountStore` (snapshot, updated-at, refreshing, refresh failed),
  `refresh_account(force, cx)`, `account_did_change(cx)`, and
  `renew(item, cx) -> Task<Result<RenewResult, UserFacingError>>` (§5.12; both D4 and D5 use it).
- **My Picks (§5.3, §5.11):** `is_picked(&BookRef)`, `set_picked(book, bool, cx)` (on the account when
  signed in, on the computer when not), the account `PicksStore`, the local store, and
  `picks_copy_offer()` / `answer_picks_copy_offer(add, cx)`.
- **Card (§5.9):** `card_number()`, `card_expires()`, `set_card_number(..)`,
  `card_symbology(cx) -> Task<BarcodeSymbology>`.
- **Navigation:** `section()`, `select(section, cx)` (pops to the root when it is already
  selected), `push(route, cx)`, `push_on(section, route, cx)`, `pop(cx)`, `stack(section)`,
  `open_search(query, cx)` / `take_pending_search()`, `open_your_books(segment, cx)` /
  `take_pending_segment()`, `request_sign_in(cx)`, `request_library_picker(cx)`.
- **Reloads:** `reload_key()` and the generations (`account_generation`, origin), as §5.2.
  `recent_searches()` / `add_recent_search(..)` / `clear_recent_searches(cx)`.

Fields are `pub(crate)`, so a feature can add its own operations in its own `impl AppState` block.

### 5.4 Persistence
- **Files:** `data_dir/LibreSpydus/` (macOS `~/Library/Application Support/LibreSpydus/`):
  - `settings.json`: the selected `LibraryInfo`, recent searches (at most 8), picks-offer answers;
  - `AccountCache/<sha256(origin)>.json`: the core's `encode_account_snapshot`;
  - `MyPicks/<sha256(origin)>.json`: the local picks, a `Vec<BookRef>`.
- **Saved pages (§5.13):** `cache_dir/LibreSpydus/SavedPages`, through the core.
- **Secrets:** keychain services `com.librespydus.desktop.session`, `.verification`, `.card`, with
  the origin as the account name.
- **Demo mode** keeps the session, card number and account snapshot in memory, as on the phones.
- **`--data-dir <dir>`** moves all files under `<dir>` and keeps secrets in memory. **`--reset`**
  deletes the files (and, without `--data-dir`, this app's keychain items) before launch.

### 5.5 Navigation
- A left **sidebar** replaces the tab bar: **Home · Your Books · Search · My Picks · Profile**, in
  the same order with the same labels (`Copy::Tabs`).
  - The sidebar header shows the library: its logo, its name, and Change library.
  - The footer shows the account name with Sign out, or Sign in.
- Each section keeps its own back stack, like a phone tab. Routes are `Detail(BookRef)`,
  `Results { query, sort, title }`, `Collection(FeaturedLink)` and `ResultsPage { url, title }`.
  The toolbar shows a Back button with ⌘[ when the stack isn't empty.
- **Dialogs** replace sheets: Sign in, the library picker (after onboarding), My card, Reserve,
  Edit reservation, and confirmations.
- **Onboarding:** with no library selected, the whole window is the library picker.
- **Shortcuts:** ⌘1–⌘5 select a section, ⌘F opens Search and focuses its field, ⌘[ goes back,
  ⌘R refreshes the account, ⌘Q quits.
- **Links:** Featured `web` links and "Open website" open in the default browser (`cx.open_url`).

### 5.7 Debug launch flags (`cfg(debug_assertions)` only; §5.6 of native-apps.md)
- `--library <origin>` skips the picker. `--demo` turns on demo mode, signed in as
  "Test Borrower". `--reset` clears saved state first. `--data-dir <dir>` (§5.4).
- `--route home | search:<q> | results:<q> | detail:<url> | borrowed | borrowed:reservations |
  favourites | profile | libraries | login | card | gallery`.
- `--window <W>x<H>`, defaulting to 1280x820. The window can't be made smaller than 960x640.
- `--evidence`: don't activate the app or take focus; the window goes at a fixed position.
- `--screenshot <png>` and `--screenshot-after <s>` (default 6): after the delay, the app renders
  its own window to the PNG with `window.render_to_image()` and quits. This needs the cargo
  feature **`evidence`** (`gpui-kit/test-support` + `image` with png), which is off by default.
  See `docs/gpui-kit-notes.md`.
- `--demo-refresh-fails`.
- **Timing log (debug):** the core's `TimingSink` prints `⏱ core …` lines and `CoreBackend` prints
  `⏱ app …`, as on iOS.

## 6. Screens (native-apps.md §6, desktop layout)
- **Content width:** each screen's column is centred, at most ~1040 pt wide. Shelves scroll
  horizontally. Lists use cards.
- **Page frame** (`ui/style.rs`): every page, the book page included, uses that column, so edges
  and titles line up from page to page.
  - A page starts `PAGE_TOP` (8 pt) under the toolbar and ends `PAGE_BOTTOM` (32 pt) under its
    last line.
  - `PAGE_GAP` (24 pt) separates the header (title row) from what follows, and Home's sections
    from each other. A page whose header stays put while the rest scrolls splits the gap: half
    under the header, half over the scrolling part.
  - Section titles (Your Books, Search, My Picks, Profile) use `page_title` in the greeting
    size; pushed pages (results, collections) title in the smaller title size.
  - The toolbar's Back lines up with the column: its chevron starts at the title's edge.
- **Home:** the header has the logo, greeting and My card. Then:
  - the search field, which opens Search;
  - New arrivals;
  - Popular genres, as a tile grid;
  - Featured;
  - Your loans.
- **Search and results:** the field, sort (Relevance / Newest) and recent searches, then result
  rows with infinite scroll.
- **Book detail:** a navy panel holds the cover, title, author, availability, format chips, the
  Reserve pill or held-status pill, and the My Picks bookmark. Below it, a white sheet holds the
  synopsis, subjects, details and branch holdings. In a wide window those two form the left column
  and the other books (similar, by the author, in the series, other editions) fill the right one as
  cover grids; each side scrolls on its own, and while the book loads the right side shows
  placeholder grids. Narrow, it's one column, with the other books at the end of the sheet.
- **Your Books:** a segmented control beside the title switches between Loans | Reservations;
  "Updated …" sits next to the refresh button at the row's right end. The reservation group
  headers show counts. Each card has a "…" menu button and the same actions on right-click: Renew,
  or Edit / Cancel. The footnote is `yourBooks.rightClickHint` / `loanRightClickHint`.
- **My Picks:** a cover grid. Right-click or "…" removes a book.
- **Profile:** a settings-style page. It drops the Face ID switch and the alert switches in v1.

## 7. Design system

### 7.1 Tokens → theme (`src/theme.rs`)
- `design/tokens.json`, mapped by hand, with a cargo test that reads `../design/tokens.json` and
  checks every value (as iOS `ThemeTokensTests`).
- Apply it with `Theme::change(ThemeMode::Dark, None, cx)`, then `Theme::update(cx, |t| …)`:

| gpui-kit `Theme` field | Token |
|---|---|
| `background` | `background` (navy) |
| `foreground` | `textPrimary` |
| `muted_foreground` | `textSecondary` |
| `primary` | `primary` |
| `primary_foreground` | `onPrimary` |
| `border` | `divider` |
| input | `field` |
| `sidebar*` | the phones' tab bar: `tabBar` (white), `tabActive` (navy), `tabInactive` |

- Dialogs are white (`sheet` / `onSheet`, set by `ui::sheet_dialog`), like the phones' system
  dialogs. Menus, dropdown lists and other popovers are dark (`popover` = `surface`, text
  `textPrimary`), because gpui-kit draws their items in the theme's `foreground`.
- Dialog buttons follow native-apps.md §7 "Dialogs": a destructive action is red, every other
  button neutral, the confirming one bold, and coral never appears in a dialog.
- Type sizes are the tokens' sizes; radii and spacing likewise.

### 7.2 Shared components (`src/ui/`, D1)
The phones' set, so the screens line up:
- CoverImage (`img(url)` with a generated placeholder: title on a genre colour), ShelfCover, BookRowCard;
- SectionHeader (+ View All), SearchField, PrimaryPillButton (coral gradient), CircleIconButton;
- GenreTile, Chip, LoadingView, EmptyStateView, ErrorStateView (Retry);
- toast helpers, ConfirmDialog, CardMenu (the "…" button plus the same right-click menu).

The debug `--route gallery` shows them all.

### 7.3 Accessibility
Every control has an `.id(..)` and a role or `aria_label` (`Copy` text). That is what VoiceOver
(AccessKit) and the headless UI tests (§9) find.

## 8. Copy (native-apps.md §7.1 applies)

### 8.1 Generated Rust copy
`design/scripts/gen_copy.py` gains a third output, `desktop/src/copy.rs`:
- a module per group (`Copy::YourBooks`, …);
- `pub const` for plain strings;
- `pub fn` with a parameter per placeholder for strings with placeholders and for plurals;
- `count: i64` with digit grouping;
- Rust keywords escaped (`r#use`).

Swift and Kotlin output must not change except for doc comments on variant keys. `--check` covers
all three.

### 8.2 Platform variants
A leaf may be a variant dict that lists **every** platform, `{"ios": …, "android": …,
"desktop": …}`. Each value is a string or, for a plural, `{"one","other"}`, and all values have
the same kind and placeholders. Use a variant only where a desktop can't say the phones' words.
D1 adds these:

| Key | Desktop text |
|---|---|
| `picks.subtitlePhone` | Saved on this computer |
| `picks.emptyPhoneMessage` | Click the bookmark on a book to save it on this computer. |
| `picks.emptyAccountMessage` | Click the bookmark on a book to save it to your library account. |
| `picks.loadFailed` | Couldn’t load My Picks from this computer. |
| `picks.saveFailed` | Couldn’t save My Picks on this computer. |
| `picks.offerTitle` | Add this computer’s picks to your library account? |
| `picks.offerMessage` (plural) | 1 book saved on this computer can be added to My Picks on your library account. / {count} books saved on this computer can be added to My Picks on your library account. |
| `profile.verified` | Verified on this computer |
| `yourBooks.noReservationsMessage` | Click Reserve on any book and follow it here until it’s ready to collect. |

New keys, following the touch-and-hold precedent in `design/copy-decisions.md`:
- `yourBooks.rightClickHint`: "Right-click a reservation to edit or cancel it."
- `yourBooks.loanRightClickHint`: "Right-click a loan to renew it."
- A `desktop` group for desktop-only words (the app menu's "Quit LibreSpydus", …).

The glossary row for the reader's device says **computer** on desktop.

## 9. Build, test & evidence
- **Build and test:**
  `cd desktop && cargo build && cargo test && cargo clippy --all-targets -- -D warnings`.
  A clean build takes about a minute. A worktree's `desktop/target` is 4–5 GB, so delete it when
  your task is done.
- **Unit tests:** AppState, the stores, the backends, formatting, theme tokens.
- **Headless UI tests:** gpui-kit's `test-support` feature (a dev-dependency):
  - `#[gpui_kit::test] fn t(cx: &mut TestAppContext)`
  - `gpui_kit::test::{TestWindowExt, …}`: `window.click("id", cx)`, `window.input("text", cx)`,
    `window.find("id").value()`, `cx.wait_for(..)`.
  - They run with `FakeBackend` or a `DemoBackend` whose public reads are faked.
  - Every feature tests its main flows this way (sign in, search, Reserve, cancel, edit, renew,
    My Picks).
- **Copy:** `python3 design/scripts/gen_copy.py --check` and `python3 design/scripts/check_copy.py`
  must pass.
- **Evidence:** run
  `desktop/scripts/screenshot.sh <out.png> [--wait <s>] -- --data-dir <dir> --demo --library https://canning.spydus.com --route <route>`.
  It builds with `--features evidence`, runs the debug binary with
  `--evidence --screenshot <out.png> --screenshot-after <s>`, and waits for it to exit.
  - Take a screenshot of every screen and state you built (signed out and in, loading, empty,
    error, each dialog). Save them under `/tmp/librespydus-evidence/<task>/` on mini-knit; they are
    not committed.
  - Look at them before you report (Read the PNG), and compare with the phone apps' look in
    native-apps.md §6–§7.
- **Report** (`worker_done`): what you built, files changed, the commit hash on your branch, the
  exact build/test commands and their results, screenshot paths, deviations, open issues, and
  any new copy keys.

### 11.2 Verification (E2)
- **The helper is the same binary,** `librespydus --verify-helper <origin> <user-agent>`, started
  as a child process. It has its own tao event loop and a wry web view on the library's origin,
  with the core's `user_agent()`.
  - It watches the web view's cookies for `aws-waf-token` on the library host
    (`cookies_for_url`).
  - When the cookie appears, it prints `aws-waf-token=<value>` on one stdout line and exits 0.
  - If the reader closes the window, it exits 1.
  - It never injects scripts into the page or interacts with the check.
- **In the app:** on `HumanVerificationRequired`, a white dialog appears. It says
  `verification.message`, with the desktop variant "Complete the check in the window that opens.",
  and offers Open check / Cancel. Then:
  - the app runs the helper and calls `AppState::complete_verification(cookie)`;
  - the screen that failed retries, through `reload_key`;
  - after two completed checks that still fail, the error is `verificationUnavailable`, as on iOS.
- **Safety:** a worker may open the helper on a UK library only to see that it renders, then
  close it. Nobody solves or automates the check (native-apps.md §2.3).

### 11.3 Alerts (E3)
- **When it checks:** at start, after every fresh account snapshot, and at 07:45 local time each
  day while the app runs. It uses the core's `ready_alerts` / `due_reminders`, with
  `patron_item_key` (§5.8).
- **Delivery:** macOS notifications. Clicking one opens the book page, or Your Books (§5.8 "Tap").
- **Profile Notifications section:** Ready to collect and Due-date reminders switches, with
  subtitles, and the blocked state.
- **State:** `alerts.json` in the data dir: per-origin alerted keys, the switches, and the last
  reminder date. Sign-out clears that library's entry.
- An unbundled binary may be unable to post system notifications. Test with a bundle (E5's
  script, or a throwaway one under /tmp), and fall back to an in-app toast when posting fails.

### 11.4 Touch ID (E4)
- **Behaviour:** as §5.14, with `{method}` = `biometrics.touchId`. The offer appears after a
  typed sign-in. Profile has a switch. `NotLoggedIn` triggers the sign-back-in. The sign-in dialog
  gets a "Sign in with Touch ID" button and `login.privacyNoteBiometrics`. Desktop variants say
  "computer" where the phones say "phone".
- **Storage:** biometry-protected Keychain items, with `.biometryCurrentSet` in the
  data-protection keychain, need an app signed with a team and an entitlement. A dev or ad-hoc
  build doesn't have one. So v1 does this:
  - keeps `{username, pin}` per origin in the login keychain through `keyring`, service
    `com.librespydus.desktop.signin`, the same protection as the session token;
  - gates every use with `LAContext evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)`;
  - stores the username in plain text beside it, under `com.librespydus.desktop.signin.username`.
  - The code is structured so that a signed build can switch to the data-protection keychain
    later. Say so in the README.
- **Testing:** mini-knit has no Touch ID, so the check is "unavailable" there. Cover the flows with
  a fake vault and a fake check. The user tests Touch ID itself on the MacBook.

### 11.5 Packaging (E5)
- **Command:** `desktop/scripts/bundle.sh [--dmg]` makes a release build into
  `desktop/target/LibreSpydus.app`.
- **Info.plist** (from `desktop/packaging/Info.plist`): `CFBundleIdentifier`
  `com.librespydus.desktop`, the name and version from Cargo.toml, `LSMinimumSystemVersion` 13.0,
  and `NSHighResolutionCapable`.
- **Icon:** `AppIcon.icns`, built from `ios/LibreSpydus/Resources/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png` with `sips` + `iconutil`.
- **Signature:** ad-hoc, `codesign --force --deep -s -`, then `codesign --verify`.
- **README:** an Install section.
